# خطة بناء Management Console — غرفة قيادة المدير

## الهدف
تحويل المحرك الحالي (CLI + ملفات مراقبة) إلى منتج إداري: لوحة ويب حية للمراقبة والتحكم، بنفس العملية، بصلاحيات ثلاثية، مع بقاء التداول الحي مقفولًا بموافقة متعددة الخطوات. القرارات المعتمدة: **FastAPI + واجهة مدمجة (بدون npm) — عملية واحدة (الحلقة في خيط خلفي) — توكنات ثابتة + 3 أدوار**.

## البنية

```
المتصفح (index.html + app.js + style.css — ثنائي اللغة AR/EN)
        │ REST + SSE (تحديث حي كل 2-5 ثوان)
┌───────┴────────────────────────────────────────────┐
│ pyrobot/console/  (python -m pyrobot.console)       │
│  app.py    → FastAPI + جلسات موقعة (HMAC)           │
│  auth.py   → مدير/مطور/مشاهد + بوابات الأدوار        │
│  supervisor.py → RuntimeSupervisor (دورة حياة الحلقة)│
│  api.py    → مراقبة + تحكم + SSE                     │
├─────────────────────────────────────────────────────┤
│ خيط خلفي: TradingLoop + TradingPipeline (الموجود)     │
│ Pipeline · RiskManager · OrderManager · AuditLedger  │
└─────────────────────────────────────────────────────┘
```

## 1. `pyrobot/console/supervisor.py` — مشغّل الحلقة
- `RuntimeSupervisor`: يملك خيط `TradingLoop`، حالة `STOPPED/STARTING/RUNNING/PAUSED/STOPPING`، آخر خطأ، لحظة آخر شريط.
- `start(config)` / `stop()` / `pause()` (إيقاف بين الأشرطة عبر `stop_event` دون قتل الخيط) / `resume()` / `apply_config(new)` = إيقاف رشيق ثم إعادة تشغيل بالإعدادات الجديدة (profile, symbols, signal_source, bar_interval, balance).
- يعيد استخدام الموجود: `build_default_pipeline`, `build_alpaca_pipeline`, `alpaca_polling_provider`, `generate_replay_data` من `runtime/loop.py` دون تكرار.
- كائن `ConsoleConfig` الوحيد القابل للتغيير من الواجهة (لا تكوين مبعثر).

## 2. `pyrobot/console/auth.py` — الصلاحيات
- أدوار: `MANAGER` (كل شيء) / `DEV` (مراقبة + سجلات وaudit، بلا تحكم) / `VIEWER` (نظرة عامة وتقارير فقط).
- توكنات من `PYROBOT_CONSOLE_TOKENS="manager:T1,dev:T2,viewer:T3"` + سر توقيع `PYROBOT_CONSOLE_SECRET`؛ جلسة ككوكي موقّع؛ `require_role(...)` كـ FastAPI dependencies.
- **بوابة التداول الحي (خطوتان + قفل بيئة)**: نقطة `live-unlock` ترفض دائمًا إلا إذا: الدور مدير + `PYROBOT_ALLOW_LIVE_TRADING=true` + إدخال عبارة تأكيد نصية حرفية + تأكيد ثانٍ. كل محاولة (نجاحًا أو فشلًا) تُسجَّل في سجل التدقيق.

## 3. `pyrobot/console/api.py` — الواجهات
**مراقبة (viewer+):**
- `GET /api/overview` — حالة النظام، equity، drawdown، PnL اليومي، kill switch، circuit breaker، `data_freshness` (عمر آخر شريط/رمز)، جلسة السوق، حالة Alpaca (من مزود الاستطلاع الموجود).
- `GET /api/positions` · `GET /api/orders?state=` (من `OrderManager.active_orders/all_orders`) · `GET /api/signals` (ذيل `AuditLedger` لأحداث SIGNAL_GENERATED) · `GET /api/audit?action=&limit=` (dev+) · `GET /api/metrics/history` (منحنى equity من `data/metrics/*.jsonl` الموجود).
- `GET /api/stream` — SSE يدفع لقطة overview دوريًا/عند التغير.

**تحكم (manager فقط، كل فعل يُسجَّل في التدقيق):**
- `POST /api/control/start|stop|pause|resume` · `POST /api/control/config` (تطبيق بإعادة تشغيل رشيقة) · `GET|PATCH /api/control/risk-limits` (مع تحقق `RiskLimits.validate()`) · `POST /api/control/kill-switch/activate` و`/reset` (يتطلب `confirmed: true` كما في الواجهة الحالية) · `POST /api/control/live-unlock` (البوابة أعلاه).

## 4. الواجهة `pyrobot/console/static/`
صفحة واحدة vanilla JS + SSE (صفر npm): تبويبات **نظرة عامة** (بطاقات حية + منحنى equity بـ canvas + جداول مراكز/أوامر + تدفق إشارات + شارات صحة البيانات/الاتصال)، **التحكم** (أزرار دورة الحياة، نموذج إعدادات، نموذج حدود مخاطر، أزرار kill switch بتأكيدات، قسم live-trading مقفل بمسار الموافقة المتعدد)، **السجلات**، **تسجيل الدخول** بالتوكن. مبدّل عربي/إنجليزي. شاشة "الأسواق" تظهر Alpaca US فقط (المرحلة 1) مع IBKR/crypto كـ"قادم" غير قابل للتفعيل.

## 5. تعديلات جوهرية مطلوبة (صغيرة ومحددة)
- `risk/manager.py`: إضافة `update_limits(new: RiskLimits)` — setter مُتحقَق تحت RLock (الحالة: `limits` للقراءة فقط).
- `runtime/pipeline.py`: إضافة `last_bar_at` (وعمر البيانات لكل رمز) إلى `status()` — أساس شارة fresh/stale.
- `audit/ledger.py`: إضافة `AuditAction.CONTROL_ACTION` (لأحداث وحدة التحكم).
- `pyproject.toml`: extra جديد `console = ["fastapi>=0.110", "uvicorn>=0.29"]` + إضافتهما إلى `dev` (لتشغيل اختبارات الـ CI).
- الربط الافتراضي `127.0.0.1:8080` (`PYROBOT_CONSOLE_HOST/PORT`) — أمان افتراضي.
- Docker: هدف `console` في Dockerfile (يثبت `.[console,alpaca]`) وخدمة `console` في compose (تحل مكان `bot` — تشغّل الحلقة واللوحة معًا بوضع replay افتراضيًا).

## 6. الاختبارات (`tests/test_console.py`)
- مصفوفة الأدوار (403 الصحيحة لكل زوج دور/نقطة) · دورة start/stop/pause/resume مع replay حتمي · PATCH حدود صالحة/فاسدة · kill switch تفعيل + إعادة ضبط تُشترط `confirmed` · live-unlock يُرفض بدون علم البيئة وبعبارة خاطئة · تدقيق كل فعل تحكم · أشكال overview/positions/orders/signals بعد صفقة مفروضة · SSE (أول حدث يُفكّ بنجاح) · حتمية لا تعتمد على توقيت (بولينج بسيط بدل sleep).

## 7. حدود النطاق (موثقة في الواجهة نفسها)
خارج هذه المرحلة: شاشات IBKR/crypto القابلة للتفعيل (تظهر معطلة "قادم")، بث websocket للبيانات، UI للاختبار الرجعي، إدارة مستخدمين كاملة — كلها مراحل لاحقة فوق نفس البنية.
