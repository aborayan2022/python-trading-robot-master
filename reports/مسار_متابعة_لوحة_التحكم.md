## 1. التشغيل

```bash
cd /home/ahmed/worke/python-trading-robot-master
# الوضع الافتراضي: profile=replay, auto_start=true (يُشغّل حلقة التداول تلقائيًا)
```

- **التوثيق التفاعلي (Swagger) لكل نقطة نهاية:** http://127.0.0.1:8080/api/docs

## 2. الدخول والصلاحيات (RBAC — ثلاثة أدوار)

| الدور | الصلاحيات |
|---|---|
| `viewer` | المراقبة فقط: overview، مراكز، أوامر، إشارات، مقاييس |
| `dev` | كل ما يخص `viewer` + سجل التدقيق الآمن |
| `manager` | كل شيء + التحكم (تشغيل/إيقاف/تعديل/حدود مخاطر/كيل-سويتش/فتح حي) |

رموز التطوير الافتراضية (في غياب `PYROBOT_CONSOLE_TOKENS`):
`manager-token`, `dev-token`, `viewer-token`.

```bash
# تسجيل دخول كمدير — يولّد جلسة موقّعة HMAC في ملف cookies.txt
curl -X POST http://127.0.0.1:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"token":"manager-token"}' -c cookies.txt

# التحقق من الدور والصلاحيات
curl -b cookies.txt http://127.0.0.1:8080/api/auth/me
```

## 3. نقاط نهاية المراقبة (Monitor — `viewer` فأعلى)

### 3.1 لمحة عامة لحظية — `GET /api/overview`
المصدر الأمثل للبدء. يعرض في استجابة واحدة:
- **الحالة العامة** `state` (STOPPED / STARTING / RUNNING / PAUSED / STOPPING / ERROR).
- **حقوق الملكية** `equity`، **الانسحاب** `drawdown`، **ربح/خسارة اليوم** `daily_pnl`, `daily_loss_pct`.
- **حالة الموثوقية:** `kill_switch_active`، `kill_switch_triggered`، `circuit_breaker.state` (CLOSED/TRIPPED) و`scale`، و`model_risk_scale`.
- **جلسة السوق** `market_session.is_open` و`session` (REGULAR/CLOSED).
- **حالة الوسيط** `alpaca_status` (connected/mode/allow_live).
- **إحصائيات المعالجة** `bars_processed`, `last_bar_at`, `data_freshness`.

### 3.2 المراكز — `GET /api/positions`
`[{symbol, quantity, entry_price, current_price, market_value, unrealized_pnl, unrealized_pnl_pct}]`.

### 3.3 الأوامر — `GET /api/orders?state=OPEN`
الأوامر عائدة من `OrderManager`؛ استخدم `?state=` للتصفية (OPEN/FILLED/REJECTED...).

### 3.4 الإشارات — `GET /api/signals?limit=50`
أحدث إشارات التداول المُولّدة (تُقرأ من سجل التدقيق).

### 3.5 سلسلة المقاييس الزمنية — `GET /api/metrics/history?limit=200`
سجل المقاييس من ملف `data/metrics/runtime_metrics.jsonl` (الحد الأدنى 10، الأقصى 2000).

### 3.6 بث لحظي (SSE) — `GET /api/stream`
بث Server-Sent Events يدفع `overview` لحظيًا للواجهة (يُحدَّث كل ~2 ثانية).

## 4. سجل التدقيق (Audit — `dev` فأعلى) — **مصدر الحقيقة**

`GET /api/audit?action=SIGNAL_GENERATED&limit=100&offset=0`
- سجل **غير قابل للتلاعب** (سلسلة checksum لكل حدث) في `data/audit/ledger.jsonl`.
- يتضمن أحداثًا مثل `MARKET_DATA_RECORDED`, `SIGNAL_GENERATED`, `ORDER_*`, `RECONCILIATION_RUN`, `KILL_SWITCH_*`, `LIVE_UNLOCK_*`.
- **يوصى بمراجعته يوميًا** أثناء أي تشغيل، فهو يوثّق كل إجراء بدون إمكانية مسحه.

## 5. نقاط نهاية التحكم (Control — `manager` فقط)

| العملية | نقطة النهاية | ملاحظات |
|---|---|---|
| تشغيل | `POST /api/control/start` | |
| إيقاف | `POST /api/control/stop` | |
| إيقاف مؤقت | `POST /api/control/pause` | |
| استئناف | `POST /api/control/resume` | |
| تعديل الإعدادات | `POST /api/control/config` | profile/symbols/signal_source/bar_interval/... |
| حدود المخاطر (قراءة) | `GET /api/control/risk-limits` | |

| إعادة كيل-سويتش | `POST /api/control/kill-switch/reset` | يتطلب `confirmed:true` |
| فتح التداول الحقيقي | `POST /api/control/live-unlock` | خطوتان + `PYROBOT_ALLOW_LIVE_TRADING=true` |

## 6. الأمان والقيود الحرجة

- **التداول الحقيقي مقفول افتراضيًا.** فتحه يتطلب:
  1. إعداد `PYROBOT_ALLOW_LIVE_TRADING=true` على الخادم (حارس بيئي).
  2. العبارة الحرفية `I UNDERSTAND THE RISKS OF LIVE TRADING`.
  3. تأكيد ثانٍ صريح (`second_confirmation:true`).
  4. كل محاولة (نجاحًا أو فشلًا) تُسجَّل في سجل التدقيق مع IP العميل.
- **كيل-سويتش** متاح للمدير فقط مع تأكيد صريح.
- روؤوس أمان (nosniff/X-Frame-Options/Referrer-Policy...) مفعّلة على كل الردود.

---

## 7. روتين المتابعة اليومي المقترح للمدير

1. `GET /api/overview` → تحقق `state=RUNNING`, `kill_switch_active=false`, `circuit_breaker.state=CLOSED`.
2. `GET /api/audit?limit=100` → راجع `RECONCILIATION_RUN` (يجب أن يكون `mismatches: []` و`ok: true`) و`KILL_SWITCH_*`.
3. `GET /api/positions` و`GET /api/orders?state=OPEN` → طابق المراكز مع المتوقع.
4. `GET /api/metrics/history?limit=200` → راجع الانسحاب والربح/الخسارة اليومية.
5. عند أي خلل: فعّل كيل-سويتش (activate) ثم حلّل من `data/audit/ledger.jsonl` قبل إعادة التشغيل.

> **قاعدة حاكمية ثابتة:** لا يوجد اعتماد على أرقام `net_pnl` وحدها؛ راقب دائمًا `state`/`kill_switch`/`circuit_breaker`/`n_trades` قبل أي حكم على الأداء.
