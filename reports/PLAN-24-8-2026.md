# خطة تطوير إنتاجية لمشروع `python-trading-robot` عبر Alpaca

## الملخص

الهدف هو نقل المشروع من نواة تداول ورقية واعدة إلى منصة إنتاج حقيقية للأسهم عبر Alpaca، مع مسار إلزامي: **بيانات حية موثوقة → تدريب ML قابل للتكرار → تداول ورقي موثق 3-6 أشهر → تداول حي برأس مال صغير وحدود صارمة**.

القرار المعتمد: أول إصدار إنتاجي يركز على **الأسهم عبر Alpaca** فقط، مع منع التداول الحي افتراضيًا حتى اجتياز بوابات قبول كمية وتشغيلية واضحة.

## التغييرات الأساسية

- **بيانات Alpaca الحية**
  - إضافة مزود بيانات Alpaca داخل طبقة `data` يدعم historical bars وlatest quote وpolling أولًا.
  - ربط `TradingLoop` بمصدر بيانات حقيقي بدل replay synthetic.
  - إضافة حماية stale data: إذا تأخرت البيانات أو فُقدت شمعة لأي رمز، يتم رفض الإشارات أو تفعيل kill switch حسب الشدة.
  - توحيد timestamps إلى UTC، والتحقق من ساعات السوق، والعطلات، والفجوات.

- **مسار ML إنتاجي**
  - بناء pipeline تدريب رسمي: تحميل بيانات تاريخية من Alpaca، استخراج features، بناء labels، walk-forward training، ثم تسجيل النموذج في `ModelRegistry`.
  - اعتماد baseline إلزامي قبل النماذج الثقيلة: `LogisticDirectionModel` مقابل buy-and-hold ومقابل استراتيجية SMA بسيطة.
  - إضافة LightGBM + Isotonic calibration خلف نفس واجهة النموذج، بشرط ألا يدخل الإنتاج إلا إذا تفوق out-of-sample بعد التكاليف.
  - منع اختيار نموذج كبطل إلا إذا امتلك artifact محفوظًا، hash صحيحًا، تقرير walk-forward، ونتائج مقارنة ضد baselines.

- **التداول الورقي الإنتاجي**
  - تشغيل Alpaca paper account فعليًا عبر `TradingPipeline`.
  - إضافة reconciliation دوري بين حالة النظام وحالة Alpaca: cash، positions، open orders، fills.
  - أي mismatch جوهري يوقف التداول ويفتح حدث تدقيق.
  - إضافة order lifecycle كامل: submit، poll، partial fill، cancel، reject، timeout.
  - تفعيل حدود صارمة افتراضية: max position، max daily loss، max open orders، max symbol exposure، max model drift scale.

- **المراقبة والتشغيل**
  - إضافة metrics منظمة: equity، drawdown، realized/unrealized PnL، fill latency، rejected orders، stale data، drift، kill switch events.
  - إخراج metrics بصيغة قابلة للقراءة من Prometheus أو JSONL كمرحلة أولى، ثم Grafana في المرحلة التالية.
  - إضافة تقرير يومي تلقائي: الصفقات، الأداء، الانزلاق، الأخطاء، قرارات النموذج، وحالة السجل.
  - إضافة runbook تشغيلي: كيف يبدأ النظام، كيف يتوقف، متى يتم تعطيل التداول، وكيف تتم مراجعة سجل التدقيق.

- **تنظيف الجاهزية الهندسية**
  - سداد دين mypy في الوحدات القديمة تدريجيًا حتى يصبح الفحص الصارم على كامل `pyrobot`.
  - تحديث README وملفات التشغيل لتوضح أن live trading معطل افتراضيًا.
  - فصل الإعدادات إلى profiles واضحة: `replay`, `alpaca_paper`, `alpaca_live_locked`.
  - عدم إضافة crypto أو IBKR أو وكلاء LLM قبل نجاح مسار Alpaca paper.

## بوابات القبول

- **بوابة البيانات**
  - historical download يعمل لرموز متعددة.
  - polling ينتج bars منتظمة خلال ساعات السوق.
  - stale feed يؤدي إلى رفض التداول أو إيقافه.
  - اختبارات تغطي انقطاع البيانات، شموع ناقصة، timestamps غير مرتبة، ورمز بلا سعر.

- **بوابة النموذج**
  - walk-forward ينتج تقريرًا موحدًا out-of-sample.
  - النتائج تشمل Sharpe، max drawdown، turnover، hit rate، profit factor، costs، slippage.
  - لا يتم اعتماد النموذج إذا لم يتفوق على buy-and-hold وSMA بعد التكاليف.
  - calibration report يثبت أن الاحتمالات ليست مضللة.

- **بوابة الورقي**
  - تشغيل 3-6 أشهر على Alpaca paper دون تدخل يدوي.
  - سجل تدقيق كامل وقابل للتحقق.
  - لا position mismatch غير مفسر.
  - لا أوامر عالقة دون cancel أو reconciliation.
  - drawdown ضمن الحدود المتفق عليها.

- **بوابة التداول الحي الصغير**
  - live mode يبقى مقفولًا افتراضيًا ويتطلب flag صريحًا مثل `PYROBOT_ALLOW_LIVE_TRADING=true`.
  - رأس المال الأول صغير ومحدد مسبقًا.
  - kill switch، daily loss limit، stale data protection، reconciliation كلها mandatory.
  - أي فشل في البيانات أو المصالحة أو السجل يوقف التداول فورًا.

## خطة الاختبار

- اختبارات وحدة لمزود بيانات Alpaca باستخدام mocks: latest quote، historical bars، rate limits، network errors.
- اختبارات تكامل لمسار `AlpacaDataProvider → TradingLoop → TradingPipeline → PaperBroker/AlpacaBroker`.
- اختبارات backtest وwalk-forward على بيانات تاريخية ثابتة محفوظة أو fixture مصغر.
- اختبارات safety: stale data، order rejection، partial fill، cancel timeout، position mismatch، model drift.
- تشغيل إلزامي قبل الدمج:
  - `pytest tests/`
  - `ruff check pyrobot/`
  - `mypy pyrobot`
  - تشغيل replay smoke test
  - تشغيل Alpaca paper smoke test عند توفر مفاتيح API

## الافتراضات المعتمدة

- السوق الأول: الأسهم الأمريكية عبر Alpaca.
- وضع الإنتاج الأول: Alpaca paper، ثم live صغير فقط بعد 3-6 أشهر نتائج موثقة.
- لا يتم توسيع النطاق إلى IBKR أو crypto أو options قبل إغلاق مسار Alpaca.
- لا يتم إضافة LLM agents أو foundation models قبل إثبات baseline ML مربح أو على الأقل غير مضلل.
- معيار النجاح ليس “النظام يعمل”، بل “النظام يعمل بأمان، يقيس أداءه بصدق، ويملك دليلًا موثقًا على alpha بعد التكاليف”.
